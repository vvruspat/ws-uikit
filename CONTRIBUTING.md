# Contributing — Styling & Tokens

Правила стилизации WS-UIKit. Кит должен полностью перебрендиваться через CSS — подключением
правильного набора токенов, без правки компонентов и без JS-темизации.

## 1. Четыре слоя токенов

Значение течёт строго сверху вниз, каждый слой ссылается **только на слой ниже**:

```
компонент(.module.css)
  → --_private            (внутренние переменные компонента, *.vars / верх .module.css)
     → --<comp>-*         (component token — публичный API кастомизации компонента)
        → semantic         (--color-action-*, --radius-control, --gap-control …)
           → primitive      (--palette-*, --space-N, --radius-N)
```

| слой | пример | где живёт | кто меняет |
|---|---|---|---|
| primitive | `--space-8`, `--palette-primary-700` | `styles/primitives/*` | ядро, редко |
| semantic | `--color-action-rest`, `--radius-control`, `--gap-control` | `styles/semantic/*` | тема / бренд |
| component | `--button-bg`, `--button-radius`, `--button-gap` | `<Comp>.vars.css` / верх `.module.css` | опц. бренд/зона/инстанс |
| private | `--_bg`, `--_gap`, `--_flex-direction` | внутри компонента | никто снаружи |

Компоненты **не** ссылаются на primitive напрямую. Нужен размер — заведи семантическую роль
(`--radius-control`, `--gap-control`) в `styles/semantic/dimensions.css`.

## 2. Шов (seam): всё через `var()`, проп задаёт дефолт

Любое визуальное свойство — цвет, размер, **и структурное тоже** (`flex-direction`, `align-items`)
— проходит через цепочку fallback. Проп/класс задаёт **дефолт**, каскад решает финал.

```css
.flex {
  flex-direction: var(--flex-direction, var(--_flex-direction, row));
  gap:            var(--flex-gap,       var(--_flex-gap, var(--gap-s)));
}
```

- `--flex-*` — **публичный шов**, читается первым, живёт в каскаде.
- `--_flex-*` — **приватный дефолт** от пропа (можно даже инлайном: инлайн задаёт только private,
  а public остаётся свободным для override).

Разрешение: `--<pub>` (бренд/зона/инстанс) → `--_<priv>` (проп) → хардкод. Никаких
специфичность-войн — приоритет решает порядок в `var()`.

## 3. ЗАПРЕЩЕНО внутри `src/` (компоненты)

- ❌ **Инлайн-стиль с финальным значением** (`style={{ flexDirection, gap, padding }}`) — бьёт весь
  каскад, замораживает значение над брендом. Инлайн допустим **только** для записи `--_private` дефолта.
- ❌ **Прямые primitive-токены** в `.module.css` (`var(--space-4)`, `var(--radius-8)`) — сначала
  семантическая роль.
- ❌ **Заморозка скиннабельного значения проп-литералом** во внутренней композиции
  (`<MFlex gap="l">` внутри компонента как единственная ручка) — гони через свой токен:
  `<MFlex className={styles.row}>` + `.row { --flex-gap: var(--<comp>-gap, var(--gap-control)); }`.

Стилизация делается **классами**, задающими переменные, а не инлайном.

## 4. Разрешено — и обязательно

- ✅ Значения, которые компонент тюнит **под себя** (radius, gap, padding, size), идут через
  `--<comp>-*` (via `--_private`) — так его кастомизируемая поверхность перечислима из одного файла.
- ✅ Значения, которые должны жить **в лок-степе со всей системой**, ссылаются на семантику
  **напрямую**, без `--<comp>-*` обёртки. Это НЕ нарушение — обёртка тут только провоцировала бы
  расхождение. Сюда входят:
  - цвета, привязанные к глобальным ролям (`--color-action-*`, `--color-text-*`) — бренд перекрашивает
    роль один раз, все компоненты следуют;
  - фокус-ринг (`--focus-ring-width`, `--focus-ring-offset`, `--color-focus-ring`) — обязан быть
    одинаковым у всех интерактивных элементов.
- ✅ Публичное имя `--<comp>-*`, приватное `--_*`. Снаружи трогают только публичные.
- ✅ `*.stories.tsx` и клиентская аппка используют пропсы (`gap`, `variant`, `size`) свободно —
  это их API.

## 5. Механизм vs политика

Механически прогоняй через шов **всё** (дёшево и единообразно). Что из этого — официально
поддержанный брендовый нобл, решает **документированный контракт компонента**, а не наличие/отсутствие
шва. Когда бренду понадобится (RTL, density) — шов уже на месте, рефактор не нужен.

## 6. Высота override — бери самую низкую, что решает задачу

```css
[data-brand="x"] { --gap-control: var(--space-2); }   /* глобально: вся роль        */
.toolbar         { --button-gap: 0; }                  /* зонально: поддерево (наследуется!) */
<MButton className={sx.tight} />                        /* инстанс: точечно           */
```

CSS-переменные наследуются — зональный override протекает во всё поддерево. Если токен не должен
протекать, объяви его через `@property { inherits: false }`.

## 7. Каскад слоёв

`styles/index.css` объявляет порядок один раз; файлы оборачиваются в свой слой:

```css
@layer primitives, semantic, brand, components, overrides;
```

Это гарантирует, что бренд бьёт семантику, семантика — примитивы, **независимо от порядка импортов
и специфичности**.

## Чек-лист нового компонента

- [ ] `<Comp>.vars.css` (или верх `.module.css`): `--_x = var(--<comp>-x, <semantic>)` для каждой
      скиннабельной величины.
- [ ] Тело `.module.css` читает только `--_x`. Ни одного `var(--space-N)`/`var(--radius-N)`.
- [ ] Нет инлайн-стиля с финальным значением. Композиция layout-примитивов — через className+`--<comp>-*`.
- [ ] Пропсы-значения только для клиентского API; внутри — токены.
- [ ] `.module.css` обёрнут в `@layer components`.
